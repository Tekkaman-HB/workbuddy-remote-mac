# WorkBuddy Remote for Mac

使用独立 Mac App 登录普通 WorkBuddy 账号，查看、继续另一台 Mac 的本地任务。控制端无需安装 WorkBuddy，无需开放平台应用或密钥。通信经过腾讯服务中转，任务在远端 Mac 执行。

0.2.2 在本机 WorkBuddy 5.9.3 的布局基础上增加独立应用图标，统一界面图标与视觉细节，完善侧栏、菜单、设置与按钮动效。已接入真实的远端任务与模型数据。**仅保留已接入且可使用的功能，未支持的入口已经移除。**

## 打开并连接

1. 打开 `dist/WorkBuddy Remote.app`。
2. 点左下角设备图标 → “使用 WorkBuddy 账号登录”，在官方网页完成登录和账号选择。
3. 点登录窗口底部“登录完成，读取设备”，返回 App 选择目标 Mac。
4. 目标 Mac 必须运行 WorkBuddy，并开启“允许移动端连接此设备”。
5. 点击侧栏任务查看历史；Enter / ⌘Enter 发送，Shift Enter 换行。下次启动会尝试恢复上次设备。

⌘K 搜索任务标题，⌘N 新建任务，⌘, 打开设置。鼠标悬停任务行的“…”可重命名、置顶、归档或删除；删除和扩大任务权限会先确认。

## 当前能力

- 自主登录、发现设备、连接另一台 Mac，读取完整分页任务列表。
- Markdown、表格、代码复制、图片、思考与工具折叠内容；加载更早历史。
- 新建任务、文字续聊、停止、模型/专家/模式选择、远端工作空间选择。
- 账号菜单、任务搜索与筛选、任务文件目录和元数据、定时任务只读列表。
- 本客户端的主题和消息字体大小设置。
- 独立双屏应用图标与侧栏标识；菜单、场景切换、弹层和侧栏动效；遵循系统“减少动态效果”。
- 历史每 2 秒刷新，任务列表每 30 秒刷新；稳定消息复用 DOM，保留阅读位置。发送失败保留草稿，不自动重发。

## 验证与边界

- 真实账号已读取远端 Mac mini 的 196 个已有任务和 26 个工作空间，展示富文本历史和模型列表。
- 新版 App 已在真实远端 Mac 上新建独立 UI 验收任务，两轮返回同一验收标记；任务总数由 196 变为 197。既有业务会话没有写入。
- 18 项自动测试覆盖协议、断线、大目录分片、接口裁剪、富文本净化、历史合并、页面连接/创建/发送/拒绝保留草稿，以及动效中断、关闭交互和减少动态效果。
- 已移除语音、控制端附件上传、资料库/助理管理、通知、账户套餐和未接入的主机设置。连接时探测目录接口，失败的能力不显示入口；只读接口只提供只读页面。
- 功能和接口对应关系见 [功能范围](docs/2026-11-13_远程接口与功能范围.md)。
- 应用和线性图标为独立绘制，吉祥物是静态替代；设置为窗口内弹层，未完成逐像素对比。具体差异见 [界面验收](docs/2026-11-13_界面复刻验收.md)。
- 未对用户业务任务做删除、归档或权限变更的实机写入测试。长期睡眠/切网恢复仍需继续验证。
- App 仅本机签名，未做 Developer ID 公证，当前构建为本机 CPU 架构。协议来自实际互操作验证，并非稳定公开 API。

## 构建与测试

构建要求 macOS 13+、Xcode Command Line Tools 和 Node.js 22+；运行 App 只需 macOS，所有页面与脚本都已内置。

```sh
npm ci --ignore-scripts
npm test
zsh build.command
```

`MacApp/` 管理窗口与独立登录，`ui/` 是独立实现的页面，`lib/wire.mjs` 是原创通道实现。凭证仅留在登录 WebKit，内置页面通过受限原生桥调用，不接收登录令牌或通道密钥。

## 实验工具

`bootstrap.py`、`channel.mjs` 与 `verify.command` 为早期只读协议取证工具，需要本机 WorkBuddy；它们不属于 App 运行依赖。

`work/` 保存私有研究、原始回复和临时凭证，已排除在版本控制与发布包外。分享 App 或源码时不要打包此目录。

详见 [协议验证报告](docs/2026-11-13_技术验证-WorkBuddy-remote-report.md)。

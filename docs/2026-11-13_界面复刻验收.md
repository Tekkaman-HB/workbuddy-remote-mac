# WorkBuddy Mac 界面对照与验收

对照版本：本机 WorkBuddy 5.9.3；实现版本：WorkBuddy Remote 0.3.9。用途为用户自己的 Mac 远程访问原型。没有复制原版渲染器代码，界面独立实现；当前版本按用户要求移除首页吉祥物。

## 观察证据与令牌

通过原生 UI 实际观察首页、聊天页、添加菜单、模型菜单、账号菜单和设置窗口，视口为 1280 × 770 pt（截图 2560 × 1540 px）。读取本机样式确认字体栈和输入卡片圆角；其余颜色为截图近似值，不是逐像素测量。

| 层级 | 规则 | 证据等级 |
| --- | --- | --- |
| primitive | PingFang SC / system-ui；文字 12/14/16 px，首页标题 30 px | 字体栈确认，字号按截图估算 |
| semantic | 白色主区、#f7f7f7 侧栏、#eaeaea 选中、灰色辅助文字、青色连接状态 | 浅色实机观察；颜色近似 |
| component | 280 px 侧栏、52 px 会话栏、800 px 首页输入区、24 px 输入卡片圆角 | 几何对照，圆角来自样式 |

页面地图：原生窗口 → 侧栏/首页/会话/文件栏；叠层 → 设备、模型、权限、工作空间、任务菜单、账号、搜索、目录、设置、确认框。登录使用独立官方网页窗口，不在登录页创建云任务。

## 交互合同

- Enter / ⌘Enter 发送，Shift Enter 换行，中文输入法组合阶段不发送。
- ⌘K 搜索本设备任务标题，⌘N 新建，⌘, 打开设置，Esc 先关闭菜单再关闭对话框。
- 菜单方向键移动焦点，弹层 Tab 保持在当前弹层，关闭后恢复原焦点。
- 新建任务直到发送时才在远端创建；草稿在切换任务时保留。远端拒绝或网络失败保留草稿，不自动重发写操作；提交期间新输入的内容不会被旧请求确认清空。
- 轮询每 2 秒读取当前历史，每 30 秒刷新任务列表；稳定消息保留原 DOM，维护阅读位置、选择和工具折叠状态。
- 设备/会话使用代次校验，旧请求返回不覆盖当前页面。原生通道在请求前刷新临期凭证；并发读取共享一次续期。
- 会话权限使用 `fullAccess` / `bypassPermissions`，与全局偏好的 `full-access` / `default-sandbox` 区分。专家参数为 `{id}`，新任务工作路径为 `cwd`。
- 删除、归档和扩大当前任务权限显示具体对象及影响；不会静默更改远端全局偏好。

## 与原版仍有差异

- 应用与线性图标为独立绘制；首页场景、快捷分类、示例提示及吉祥物按用户要求移除。尚未做同内容逐像素差分。
- 设置采用窗口内弹层，原版为独立设置窗口；深色已在本客户端实机检查，原版深色仍未取证；窄窗口规则未做原生窗口实机验收。
- 根据用户最新要求，语音、控制端附件上传、资料库管理、助理管理、账户通知和未接入的设置已直接移除；目录入口按只读探测结果显示。
- 当前工具内容以通用折叠卡片展示，未覆盖原版所有审批、团队、多媒体、图表及专用工具组件；刷新采用轮询。
- 文件面板读取任务产出目录和元数据，尚未提供原版完整文件编辑器/浏览器/终端。
- 菜单中的任务重命名、置顶、归档、删除、专家和权限参数已按原版接口实现；实机未对用户业务任务进行这些写入测试。

本阶段按用户要求保留原版核心风格，并主动裁掉缺少已接入接口的页面；不再追求原版所有功能入口齐全。

- 独立应用图标采用双屏与助理双眼意象，青绿色底板保留 macOS 透明安全边距；ICNS 内含 16–1024 像素表示。AppKit 显式设置运行时 Dock 图标，侧栏使用同意象 SVG。图标矢量源位于 tools/generate-icon.swift。
- 界面图标统一为 24 格坐标、1.65 线宽和圆角端点；补齐悬停提示，统一按钮比例、菜单阴影、输入焦点、危险操作和浅深色对比。应用图标按本次要求独立设计，不以原版图标一致性为验收目标。
- 根据 motion-match 的 Focus Field、Sliding Content Tabs、Toast Overshoot 与 Keycap Press 模式改写为原生 CSS/Web Animations。按钮按压约 90 ms，弹层入场 220 ms、退出 130 ms，遮罩 160 ms，侧栏内容位移 260 ms；场景滑块 300 ms。未加入动画库。
- 关闭中的弹层立即退出焦点与交互；重新打开会取消旧动画，旧完成回调不会隐藏新内容。设置切换只更新内容，保留搜索框与焦点；侧栏收起后焦点移到展开按钮，展开后恢复收起按钮；最新构建已实机确认双向焦点。轮询已有消息不重复播放动画。
- 系统开启“减少动态效果”时直接完成显隐和布局切换；自动测试覆盖该分支，未修改用户系统设置。
- 实机已检查新侧栏标识、侧栏收起/展开、模型菜单、设置导航、浅深色主题及 Esc 关闭后恢复模型按钮焦点；检查后恢复“跟随系统”。未进行帧率测量或逐像素差分，Dock/Finder 图标由打包资源与原生加载路径校验。

## 0.3.1 统一预览深色模式

修复 0.3.0 将预览区固定为浅色的问题。UI 的实际主题为唯一来源，经受限 appearance 动作同步原生窗口、预览标题/按钮、加载/错误/纯文本背景；跟随系统与用户手动主题切换使用同一路径。

HTML 报告只在隔离预览中应用深色阅读样式：灰白纸面、卡片、文字和分隔线调整为与聊天区一致的深灰层次，彩色浅底转换为低亮度色调，红绿文字与图表曲线保留含义。ECharts 标题、坐标、网格、图例和 tooltip 随主题更新；同一主题重复更新不重建图表。切回浅色恢复原有样式和图表配置，原始文件字节不改写。PDF/图片保留文档内容自身颜色，仅外框跟随主题。

自动测试 29 项通过，新增主题恢复、语义色与图表幂等回归。深色适配基于报告实际 DOM 和可选 ECharts，不能视为任意第三方图表库均支持主题。

实机验收：真实 HTML 报告在深色模式下的纸面、卡片、标题、图例、坐标和网格均显示为深色层次；曲线和红绿语义色保留。手动浅色切换能恢复报告原始配色，阅读位置保留。额外修复并回归“手动浅色 → 跟随系统”时的窗口外观覆盖：原生解除窗口覆盖、读取应用实际系统外观，并返回最终主题，避免 WebKit 将手选窗口主题误认为系统主题。已恢复用户原有的跟随系统设置。
